# YouTube ナビゲーションリファレンス

YouTube がページ遷移（ナビゲーション）をどのように行うかを記述する。拡張実装とテストの双方で必要になる共有リファレンスであり、テスト側の待機ルールは `AGENTS.md` にある。

この文書が記述するのは YouTube であり、拡張機能ではない。拡張機能自体の契約は `SPEC.md` である。YouTube は予告なくこの挙動を変更する。テストがこの文書で説明されていない仕方で失敗したときは、修正とともにこの文書も更新する。

## ナビゲーションの仕組み

YouTube はシングルページアプリケーションである。アプリ内アンカーのクリックはブラウザナビゲーションを一切行わない。ルーターは次のステップで処理する:

| ステップ | 何が起こるか                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------- |
| 1        | document レベルのルーターリスナーがクリックを捕捉し、アンカーに対して `preventDefault()` を呼び出す        |
| 2        | `yt-navigate-start` が発火し、ページデータがリクエストされる（`/youtubei/v1/browse` と関連エンドポイント） |
| 3        | SPA がページを再レンダリングし、`pushState` で URL を更新する                                              |
| 4        | `yt-navigate-finish` が発火する                                                                            |

ハードナビゲーション（完全なページ読み込み）はステップ 1〜2 のクリック経路を飛ばす。初期読み込みの完了後も、ルーターは `yt-navigate-finish` を一度だけ発火する。

DOM はルーターの内部状態の準備より先にレンダリングされうる。この時間帯のアプリ内アンカーへのクリックは、ステップ 1 と 2 の間で静かにドロップされることがある。

モバイル YouTube は別の実装であり、イベント名も異なる。拡張機能は `src/entrypoints/play-all-button.content/youtube-hooks.ts` でそれらを対応付ける:

| スコープ | ナビゲーション開始    | ナビゲーション終了   |
| -------- | --------------------- | -------------------- |
| Desktop  | `yt-navigate-start`   | `yt-navigate-finish` |
| Mobile   | `state-navigatestart` | `state-navigateend`  |

## sort 切り替えはナビゲーションではない

sort チップ（Latest / Popular / Oldest）のクリックは SPA ルーターを経由しない。
`yt-navigate-start`/`yt-navigate-finish`（desktop）や
`state-navigatestart`/`state-navigateend`（mobile）は発火せず、URL のクエリも
変化しない。代わりにページはその場で更新される:

| ステップ | 何が起こるか                                                                                                                                                                                                                                    |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1        | チップの `aria-selected` が約 100 ms 以内に反転する（mobile では選択済みチップが一度 false に戻ってから true に戻ることがある）                                                                                                                 |
| 2        | 数百 ms 後に browse 応答が着き、ページが再レンダリングされる: 動画グリッドが新しい sort の動画に DOM ごと入れ替わり、desktop では同じタイミングでチップバーも再構築されて、その中に anchor されたノード（拡張機能の UI を含む）が detach される |
| 3        | 選択済みチップの再クリックでもグリッドは入れ替わる。no-op ではない                                                                                                                                                                              |

2026-09-29 に desktop・mobile のミュート済み Chromium プローブで観測。ステップ 2
より前に解決した要素は操作の途中で detach されうる。テスト側の同期ルールは
`AGENTS.md` にある。
